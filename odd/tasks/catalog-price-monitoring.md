## Shared HTTP contract
GET `/api/catalogdeals/freshness?status=all|recent|stale|missing&page=1&pageSize=20` (`UserWithId`, existing steam-read limiter) returns:
```
{asOfUtc:string, freshnessHours:72, page:number, pageSize:number, total:number, unresolvedWishlistEntries:number,
 counts:{total:number,recent:number,stale:number,missing:number},
 items:[{gameId:number,name:string,imageUrl:string|null,steamAppId:number|null,
 status:"recent"|"stale"|"missing",priceObservedAtUtc:string|null,
 providers:[{provider:string,priceObservedAtUtc:string|null,lastCheckedAtUtc:string|null}]}]}
```
`total` is selected status total, counts unaffected by filter, page clamped and bounded. A recent higher Steam price must never hide an older cheap external price. Deterministic tie: cheapest amount, latest observation among equal amounts, stable provider/key. Missing iff no usable comparable price. Same winner timestamp drives monitor status AND pending-job eligibility; per-provider dates remain separate. These are price coverage buckets, not proof all shops refreshed. Missing can be unsupported or no match, not inherently failure. Same raw query basis used by job selection; per-provider pending evaluation may be stricter than game coverage buckets but must be explicitly named. ISO UTC times; null unknown. Future timestamps must not silently qualify as valid freshness evidence.
BFF `/api/bff/discover/freshness` preserves typed errors/session rotation and uses same query contract. Job key `catalog.prices-refresh`, only default options unless existing framework needs boolean(s); manual Jobs page uses returned catalog metadata.
